The story

A one-person business, run like a product team

The owner sells counselling session with psychometric tests as small, affordable packages. The old site made that hard: fixed question sets, a handful of fixed packages, and every change — even a price — locked inside source code on a rented server.

Business logic in code

Packages, pricing and question sets were hard-wired. No cost-effective way for the owner to change what he sells.

A server to babysit

Node + React + MongoDB all on one MilesWeb VPS at ₹3,000/month — patching, deploys and downtime were the owner's problem.

Text-heavy, mobile-clunky

Dense textual pages and navigation across multiple screens — exactly the experience mobile visitors bounce off.

Rigid test workflow

A fixed set of questions that could not be tweaked, packaged or priced in smaller, customer-friendly bundles.

The rebuild inverts all of it: the website is static and free to host, the backend is a Google Sheet the owner already knows how to use, and the customer picks a custom package from the site itself — backed by token-based access for secure test delivery.

Experience

Textual clunkiness → mobile-first clarity

  • Text-heavy layouts that read like documents, not apps
  • Rigid question sets — nothing could be tweaked or bundled
  • Fixed packages; no smaller, customer-friendly cost packs

New — built mobile-first, fast

FAQ

Quick answers

For a low-volume, high-value product like psychometric tests — absolutely. Sheets handles the data volume easily, is always backed up by Google, and is a tool the owner already knows. Apps Script serves it as a JSON API to the static site.

Edit the row in the sheet — done. No rebuild, no redeploy, no developer. The change is live the next time the site fetches package data.

Token-based access: each purchase maps to a token that unlocks the test content. No passwords, no profile management, no admin workload for a one-person business.

The old mobile experience buried the offering under multiple pages of navigation. A single, section-based page puts the story, packages and test selection one scroll away — which is exactly how visitors use phones.
